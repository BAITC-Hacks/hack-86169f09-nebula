# EventMatch: OpenAI Platform и размещение в Brev

## Текущая интеграция

Провайдер объяснений — OpenAI Platform, модель по умолчанию `gpt-4.1-mini`.
Запросы отправляются только на `https://api.openai.com/v1/responses`.
Используется Structured Outputs: модель выбирает ровно два ключа существующих фактов
для каждой из максимум трёх карточек. Сервер повторно проверяет ID, факты и отсутствие
повторов. Фильтры, бюджет, порядок выдачи и формулировки фактов определяются кодом.

Документация:
- https://developers.openai.com/api/docs/models/gpt-4.1-mini
- https://developers.openai.com/api/docs/guides/structured-outputs

## Ключ и настройки

```text
AI_PROVIDER=openai
OPENAI_API_KEY=<секретный ключ OpenAI Platform>
OPENAI_MODEL=gpt-4.1-mini
```

Ключ хранится только в окружении сервера или серверном `.env` с правами 600.
Не коммитьте его, не вставляйте в клиентский JavaScript и не отправляйте в чат.
Ключ передаётся OpenAI в Authorization, не в URL. Ответы не сохраняются как Responses
объекты (`store=false`); это не отменяет применимых правил хранения данных провайдера.

Модель получает параметры запроса и факты выбранных профилей. Полный каталог не отправляется.
Основной источник — командный CSV `data/contractors.csv` из 66 профилей.
Оплата OpenAI API и оплата сервера Brev отдельные. Баланс аккаунта не проверяется кодом.

Python `run.py` не загружает `.env` автоматически: задавайте окружение в терминале/PyCharm.
Docker Compose читает серверный `.env`. `.env*` исключены из Git и Docker-контекста.

## Проверка

`GET /api/health` возвращает `ai_provider: openai` и `ai_configured` — наличие настройки,
но не подтверждение работоспособности ключа. Для реальной проверки выполните поиск
с `use_ai: true`: успешный ответ содержит `explanation_mode: ai_fact_selection`,
`ai_provider: openai`, `ai_model: gpt-4.1-mini`.

Без ключа, при ошибках авторизации/квоты, таймауте или невалидном ответе сохраняется
подбор с шаблонными объяснениями и предупреждением. `ai_error` содержит только безопасный
код причины; секреты и полный ответ ошибки провайдера не возвращаются посетителям.
Максимум 600 выходных токенов, HTTP timeout 5 секунд, ожидание результата до 7 секунд.

Автоматические тесты используют имитацию API, не расходуют баланс и не подтверждают
доступ конкретного аккаунта. Реальная проверка требует ввода ключа владельцем.

## Размещение

Сайт: https://8001-qfrtcqsej.gobrev.dev/
Хостинг: Brev/GCP, `eventmatch-nebula`, 2 CPU / 2 ГБ RAM / 100 ГиБ диска.
Согласованный тариф $0.07/час, остановленный диск $0.02/час.
HTTPS-ссылка защищена входом в аккаунт NVIDIA, который используется для управления Brev.
Доступ к модели выполняется через OpenAI и не требует NVIDIA Build или подтверждения
телефона в NVIDIA. Общедоступный режим ссылки настраивается отдельно.

Закрытый GitHub-репозиторий нельзя клонировать на сервере без авторизации. Рабочая копия
развёрнута из архива коммита, переданного по SSH. Для обновления передайте изменённые
файлы в `/home/ubuntu/workspace/eventmatch-nebula`, затем выполните там:

```text
docker compose up -d --build
docker compose ps
```

Для Brev Secure Links серверный `.env` содержит `BIND_ADDRESS=0.0.0.0`.
По умолчанию локальный Compose слушает только `127.0.0.1:8001`.
Облачный firewall не открывает порт 8001 напрямую в интернет; доступ идёт через прокси.
Контейнер работает от непривилегированного пользователя и имеет health check.
Первоначальный setup script в Brev помечен Failed из-за клонирования закрытого репозитория;
приложение позднее успешно установлено отдельно через SSH.

Для собственного шлюза поддерживается явное `AI_PROVIDER=gateway`, `AI_API_URL`, `AI_API_KEY`.
Настройки NVIDIA NIM больше не используются и не передаются в контейнер.
